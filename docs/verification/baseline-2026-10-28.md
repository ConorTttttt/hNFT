## Reproduce locally

For the complete automated pipeline, use GitHub Actions **hNFT baseline verification**
on `baseline/2026-10-28`; its two jobs are mandatory gates.

For a local development machine:

```sh
git switch baseline/2026-10-28
npm ci --prefix client
npm ci --prefix ui
bash scripts/verify-baseline.sh typescript
nix develop --accept-flake-config --command bash scripts/verify-baseline.sh holochain
```

The Holochain build is toolchain-sensitive: `flake.nix` pins the holonix 0.7 line,
and `flake.lock` is the resolver lock. Do not use host Rust as a substitute
for the Nix build when certifying the baseline.

## Explicit security limitations (do not call production-ready)

1. `dnas/nft/zomes/coordinator/nft/src/payment.rs` contains a **demo-only**
   `verify_rave_settlement` that synthesizes `fulfilled: true` without fetching
   or validating the RAVE. Its tests use deliberately fake RAVE hashes.
2. `ui/src/lib/appState.svelte.ts` passes a `fulfilled` value to the client,
   but the Rust `SettleFromRaveInput` only deserializes `nft`, `to_agent`,
   and `rave`. The "settlement fulfilled" demo checkbox therefore does not
   enforce the claimed settlement condition in the zome.
3. Both generative and blind-box flows only have a forgeable
   `dev-insecure` randomness verifier; no production randomness source exists.
4. Payment and NFT delivery are **not atomic** across DNAs. Recoveries, refunds,
   incomplete blind purchases, and disputes are not adequately implemented.
5. Blind-box batch closure gives the minter discretion to omit purchases.
6. Collection registration author does not prove collection creator identity.
7. Client-side reveal secrets have a loss/recovery risk; non-generative secrets
   should be backed up appropriately.
8. Network marketplace results are bounded samples, not an exhaustive global index.

## Manual smoke gate (not yet verified for this revision)

Run `npm start` from an ordinary unconfined terminal (see
`docs/live-walkthrough.md`). Confirm: two agents connect; A mints; A reveals;
A offers to B; B accepts; ownership and provenance update on both windows;
a third agent sees provenance; listing create/update/cancel; discovery and
joined clone state; blind-batch and generation demos; connection recovery.

Do not use real payments during the smoke gate.
